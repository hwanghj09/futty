# Futty 개발 체크리스트

Futty의 목표는 AI가 MCP로 게임을 제작하고, 실패를 재현해 수정하고, 실행 가능한 Windows 게임까지 내보내는 것입니다. 다음 작업부터는 이미 구현한 도구를 조합해 제작 시간을 줄이고 자동 검증 범위를 넓힙니다. [제품 로드맵](ai-roadmap.md) · [MCP 사용 가이드](guide.md)

## AI 원스톱 에셋 제작 확장

[디자인·2D/3D 모델링·애니메이션·사운드 원스톱 제작 계획](one-shot-asset-pipeline.md)을 별도 마일스톤으로 관리합니다. 현재 추가된 [프로토타입 생성기](../scripts/generate-prototype-assets.py)는 한 명령으로 PNG·애니메이션 GLB·WAV와 매니페스트를 생성하지만, 고품질 생성형 AI 제작/씬 자동 바인딩까지 완료된 것은 아닙니다. [2D·멀티플레이 개발 계획](2d-multiplayer-roadmap.md)과 병행합니다.

## 지금 제작에 쓸 수 있는 기능

| 기능 | 도구와 확인 범위 |
| --- | --- |
| 씬과 프로젝트 관리 | 씬 생성·검증, 오브젝트 일괄 편집·Undo, 프로젝트 생성·씬 목록·시작 씬 지정 |
| 게임 구성 | 조명·충돌체·캐릭터 편집, 에셋 가져오기와 UUID 유지 교체, 공유 재질, Rhai 작성·검사, 씬별 입력과 HUD |
| 프리팹과 씬 전환 | 프리팹 생성·배치·갱신, 상호작용이나 HUD 버튼으로 등록된 씬 전환 요청 |
| 검증과 재현 | 프로젝트의 씬·에셋·스크립트 검사, 고정 틱 플레이테스트, HUD·충돌·전환 대상 판정, 리플레이의 첫 불일치 틱 확인 |
| 결과물 생성 | 카메라의 저장된 3D 화면을 PNG로 캡처하고, 기존 Windows x64 플레이어로 `Game.exe`와 참조 에셋을 패키징 |

## 앞으로 만들 순서

| 순서 | 작업 | 완료 기준 |
| --- | --- | --- |
| **11** | **장르별 프로젝트 템플릿** | 빈 작업 폴더에 템플릿을 펼쳐 시작 씬과 실행 가능한 프로젝트를 생성한다. 코인 수집을 먼저 만들고, 이후 FPS 연습장·퍼즐·플랫폼·탑다운을 같은 방식으로 생성한다. |
| 12 | 시드 기반 레벨 배치 | 같은 시드로 방·통로·장애물·스폰을 다시 만들고, 플레이어 크기와 이동 규칙을 기준으로 시작점부터 목표까지의 경로를 확인한다. |
| 13 | 씬 변경 미리보기와 비교 | 일괄 편집을 저장하기 전에 오브젝트·컴포넌트·참조의 변경 내역과 검증 오류를 보여준다. |
| 14 | 게임 제작 스킬 확장 | 프로젝트 생성, 에셋 가져오기, 테스트, Windows 패키징에 쓸 Futty 스킬을 추가하고 각 스킬을 예제에 적용해 본다. |
| 15 | 코인 수집 게임 통합 검증 | AI가 새 폴더에서 씬·이동·수집·점수 HUD·승리 조건을 만들고, 실패를 수정한 뒤 테스트와 Windows 빌드까지 완주한다. |
| 16 | 여러 씬에 걸친 플레이테스트 | 전환 요청 후 대상 씬을 실제로 열어 로비 → 게임 → 결과를 이어서 실행한다. 씬 방문 순서, HUD 버튼, 최종 판정을 검사한다. |
| 17 | 실패 리포트와 자동 제작 파이프라인 | 프로젝트 검증 → 플레이테스트 → 카메라 캡처 → Windows 빌드를 한 번에 실행하고, 실패한 단계·씬·틱과 관련 기록을 반환한다. |
| 18 | 에셋 일괄 가져오기와 프로젝트 유지보수 | 여러 에셋을 검증·등록하고, 누락·미사용 에셋과 각 참조 위치를 조회한다. 저장 형식 변경 시 기존 프로젝트를 열고 내보낼 수 있는지 확인한다. |

**현재 검증 범위**에서 헤드리스 플레이테스트는 전환 요청 시점에 멈춥니다. 카메라 PNG는 저장된 3D 화면을 담으며, Windows 패키징은 준비된 플레이어 실행 파일을 사용합니다.
