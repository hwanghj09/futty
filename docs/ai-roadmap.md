# Futty AI-first 게임 제작 도구 로드맵

> **Futty는 AI가 게임을 쉽고 빠르게 만들기 위해 사용하는 엔진이자 도구다.** 인간이 GUI를 조작하는 것을 중심에 놓지 않는다. AI 에이전트가 엔진을 직접 호출하여 게임을 만들고, 수정하고, 검증하고, 빌드하는 흐름이 최우선이다.

## 1. 제품의 정체성

- **1차 사용자:** Codex 등 MCP, CLI 또는 API를 사용하는 AI 개발 에이전트.
- **2차 사용자:** 게임 제작을 지시하고 완성물을 검토하는 사람. 사람용 에디터는 선택적 시각화 및 보조 편집 수단이다.
- **Futty의 역할:** 씬, 렌더링, 에셋, 물리, 스크립트, 입력, UI, 실행, 테스트, 내보내기를 AI가 조작할 수 있는 기능으로 제공한다.
- **AI의 역할:** 사용자 요구를 해석하여 제작 계획을 세우고, Futty 도구로 구현하고, 오류를 보고 고친다.
- **의도적으로 구분할 것:** AI가 게임을 플레이하거나 AI끼리 대전하는 시스템이 핵심 제품은 아니다. AI NPC도 게임 제작에 필요한 선택적 기능일 뿐, 엔진 개발의 우선순위가 아니다.

**핵심 원칙: 사람이 에디터를 열거나 클릭하지 않아도 AI가 완전한 게임을 만들어 낼 수 있어야 한다.**

### 이상적인 제작 흐름

1. 사용자가 AI에게 장르, 목표, 조작, 플랫폼 등의 요구를 설명한다.
2. AI가 엔진의 기능과 프로젝트 상태를 조회하고 구현 계획을 만든다.
3. AI가 프로젝트·씬·오브젝트·카메라·조명·에셋을 생성한다.
4. AI가 게임 규칙, 물리, 입력, HUD, 오디오, 씬 전환을 연결한다.
5. AI가 검사 도구를 호출해 에셋 참조, 스크립트, 실행 결과를 확인한다.
6. AI가 오류 코드, 로그, 테스트 결과, 필요하면 스크린샷을 받아 수정한다.
7. Futty가 실행 파일과 필요한 에셋을 패키징하고 결과를 돌려준다.

예를 들어 "3D 코인 수집 게임을 만들고 Windows 실행 파일로 내보내 줘"라는 요청을 AI가 Futty 도구만으로 처리하는 것이 목표다.

## 2. 현재 상태: 실제 구현과 계획 구분

| 영역 | 현재 지원 상태 |
| --- | --- |
| 3D 엔진 | wgpu/WGSL 렌더링, ECS, Rapier 물리, Rhai 스크립트, 오디오, GLB, 애니메이션 |
| 게임 편집·실행 | 사람용 에디터에서 씬·프리팹·HUD·프로젝트를 편집하고 Play 및 Windows 내보내기 가능 |
| AI용 MCP | 씬·프로젝트 관리, 오브젝트와 컴포넌트 일괄 편집·Undo, 에셋·재질 관리, Rhai 작성·검사·연결, 씬 입력·HUD 설정, AI 관찰·행동, 헤드리스 플레이테스트와 리플레이. [사용 가이드](guide.md#codex에서-futty-mcp-사용하기) |
| AI의 전체 게임 제작 | **미구현:** AI용 오브젝트/컴포넌트/에셋/스크립트/HUD 편집, 자동 검증·테스트·빌드 등 |

아래의 도구 이름은 **제안 API**다. 구현된 5개 MCP 도구를 제외하고는 아직 존재하거나 작동한다고 가정하지 않는다. 실제 소스와 도구 정의를 확인한다.

## 3. 설계 원칙과 아키텍처

1. **GUI 독립성:** 모든 핵심 제작 작업은 에디터를 열지 않아도 MCP/CLI로 가능해야 한다. 에디터에서만 누를 수 있는 버튼을 핵심 API로 취급하지 않는다.
2. **명확한 도구 계약:** JSON 스키마, 설명, 필수값, 기본값, UUID, 좌표·단위, 허용 범위를 문서화한다. 호출 결과도 구조화한다.
3. **조회와 편집의 대칭성:** AI가 변경할 수 있는 요소는 정확히 조회·검증할 수 있어야 한다.
4. **고수준 + 저수준 기능:** 방이나 기본 컨트롤러를 일괄 배치하는 템플릿과 개별 컴포넌트를 세밀하게 수정하는 도구를 함께 제공한다.
5. **원자적 변경:** 여러 수정이 섞인 요청은 적용 전 검증하고, 도중 실패 시 롤백한다. 파일 충돌과 작업 버전을 감지한다.
6. **재현성과 반복성:** 동일한 프로젝트 입력·에셋·시드·도구 호출로 결과를 재현한다. 재시도 시 중복 생성되지 않도록 한다.
7. **기계가 읽는 피드백:** 성공/실패, 오류 코드, 대상 UUID, 필드 경로, 경고, 로그, 결과 파일 경로를 반환한다. 장시간 작업에는 진행 상태를 조회할 수 있어야 한다.
8. **모델 중립성:** AI의 추론은 외부 에이전트가 한다. Futty에는 특정 LLM의 프롬프트에 종속된 로직 대신 안정적인 제작 API를 둔다.

### 설계 구조

- **엔진 공통 계층:** futty-core, futty-runtime, futty-assets, futty-render 등의 재사용 가능한 데이터와 로직.
- **제작 서비스 계층(확장 예정):** 프로젝트·씬·에셋 수정, 검증, 테스트, 패키징을 제공하는 UI 독립 Rust API.
- **AI용 MCP(확장 예정):** 제작 서비스 계층을 AI 도구로 제공. 도구 설명과 스키마를 풍부하게 유지.
- **CLI(확장 예정):** 배치 편집, 테스트, 자동 빌드를 제공. MCP와 같은 제작 서비스를 사용.
- **사람용 에디터(기존):** 결과 확인과 선택적 수동 편집. 내부 서비스 사용으로 기능 중복을 줄인다.

## 4. P0 — AI가 게임 하나를 처음부터 끝까지 만든다

P0의 최종 목표는 **AI의 도구 호출만으로 작지만 완성된 3D 게임을 만들고 Windows 게임으로 빌드**하는 것이다.

### P0-A. 프로젝트와 씬 편집을 AI에 개방

| 제안 API | 목적 |
| --- | --- |
| project_create / project_inspect / project_set_start_scene | 프로젝트 생성·조회, 시작 씬 지정 |
| scene_create / scene_inspect | 기존 도구 활용, 상세 구조 조회 확장 |
| object_list / object_create / object_update / object_delete | 도형·카메라·조명 생성, 검색, 계층·Transform 변경, 삭제 |
| component_get / component_set / component_remove | 메시, 카메라, 조명, 충돌체, 강체, 컨트롤러 등 설정 |
| scene_apply_ops | 여러 작업의 사전 검사, 원자적 적용, 충돌 감지, 롤백 |
| scene_validate | UUID·부모·에셋·카메라·컴포넌트 오류를 기계적으로 보고 |

**검증:** GUI 없이 바닥, 장애물, 플레이어 오브젝트, 카메라와 조명을 생성하고 저장한 후 재조회한다.

### P0-B. 실제 게임 기능을 AI가 구성

| 제안 API | 목적 |
| --- | --- |
| asset_import / asset_list / asset_reimport | GLB·PNG·WAV·Ogg 등록, 참조 유지, 갱신 |
| material_create / material_update / asset_assign | 재질·메시·텍스처·애니메이션 지정 |
| script_create / script_update / script_validate / script_attach | Rhai 게임 로직 작성, 오류 위치 제공, 오브젝트에 연결 |
| input_get / input_set | 이동·점프·상호작용 등의 입력 액션과 바인딩 설정 |
| hud_create / hud_update / hud_bind | 점수·체력·버튼·게이지 생성 및 게임 값 연결 |
| prefab_create / prefab_instantiate / prefab_update | 재사용 가능한 게임 오브젝트 생성과 배치 |
| scene_transition_set | 로비·게임·결과 씬 연결 |

**검증:** AI가 이동, 점수, 상호작용, 오디오, 승리·패배 조건, HUD를 완성하고 스크립트 및 참조 검사를 통과한다.

### P0-C. GUI 없는 검증과 자동 빌드

| 제안 API | 목적 |
| --- | --- |
| project_validate | 씬·에셋·스크립트·참조·시작 씬의 종합 검사 |
| game_test | 에디터 없이 게임 로직과 입력 시나리오 실행, 기대 이벤트 검사 |
| game_logs | 구조화된 런타임·스크립트·물리 오류와 이벤트 조회 |
| game_capture | 지원되는 그래픽 환경에서 카메라 이미지 PNG로 캡처 |
| project_build | Windows 실행 파일과 의존 에셋 패키징, 결과 경로·오류 반환 |

**주의:** 헤드리스 게임 로직 테스트와 GPU 기반 이미지 생성은 별도 실행 경로다. AI가 게임을 제작하기 위해 게임을 검증하는 것과, AI 플레이어 자체를 연구·개발하는 것을 혼동하지 않는다.

### P0 통합 완료 조건

- AI가 빈 디렉터리에서 프로젝트·씬·에셋·스크립트·HUD를 모두 생성한다.
- 별도의 사람용 GUI 조작이나 수동 파일 편집 없이 모든 제작 단계가 완료된다.
- 검증·테스트 API가 구조화된 오류와 판정 결과를 돌려준다.
- 테스트 실패를 보고 수정한 뒤 재시험할 수 있다.
- 게임 실행 파일과 필요한 에셋이 자동으로 빌드된다.
- 동일 절차를 새 프로젝트에서 다시 실행할 수 있다.

## 5. P1 — AI의 제작 속도와 완성도를 높인다

| 기능 | 목표 |
| --- | --- |
| game_create_from_template | FPS, 퍼즐, 플랫폼, 탑다운 등의 시작 프로젝트 템플릿 |
| scene_generate_layout | 시드 기반 방·통로·장애물·스폰 배치 |
| scene_preview_ops / scene_diff | 변경 적용 전후 확인, 참조 영향 분석 |
| 에셋 일괄 임포트 | 외부 이미지/3D/오디오 생성 도구 결과 검증 및 자동 등록 |
| 실패 리포트 | 로그·이벤트·문제 오브젝트·캡처를 묶어 AI가 쉽게 디버깅 |
| 테스트 스키마 | 초기 상태, 입력 시퀀스, 기대 상태, 제한 시간 등을 파일로 선언 |
| 자동 제작 파이프라인 | validate → test → capture → build → report |
| 프로젝트 버전 관리 | 저장 포맷·리소스 마이그레이션 및 호환성 확인 |
| 다중 씬/프리팹 생산성 | 재사용 오브젝트·씬 전환·리소스 검색과 참조 수정 자동화 |

**완료 기준:** AI가 템플릿을 이용해 게임을 제작하고, 자동 테스트 결과에 맞춰 반복 수정·재빌드할 수 있다.

## 6. P2 — 복잡한 게임과 장기 프로젝트 제작

- 대규모 에셋 검색, 의존성 그래프, 미사용 리소스 관리.
- AI 작업을 위한 스냅샷, 변경 이력, 안전한 되돌리기, 여러 작업자의 충돌 조정.
- 자동 성능 분석, 회귀 테스트, 릴리스 검증과 결과 리포트.
- 장르별 게임플레이 컴포넌트 및 재사용 가능한 프리팹·템플릿 생태계.
- Windows 제작 자동화가 안정된 이후 추가 플랫폼 빌드 검토.

**AI NPC, AI 대전, AI 관전 시스템은 기본 로드맵의 필수 기능이 아니다.** 게임 제작 수단이라는 핵심 목적보다 앞서 개발하지 않는다.

## 7. 실제 구현 순서

[개발 체크리스트](development-checklist.md)에서 이미 사용할 수 있는 도구와 다음 작업의 완료 기준을 확인할 수 있습니다.

1. **futty-mcp 확장:** 오브젝트·컴포넌트의 읽기/쓰기/삭제와 배치 작업, 씬 검증부터 구현.
2. **게임플레이 제작 API:** 에셋, Rhai, 입력, 프리팹, HUD, 프로젝트·씬 전환을 API로 개방.
3. **UI 의존성 제거:** 에디터의 빌드/작업 코드를 재사용 가능한 Rust 서비스로 추출.
4. **자동 검증 및 빌드:** 프로젝트 검사, 헤드리스 로직 테스트, 오류 리포트, Windows 빌드.
5. **AI 생산성 강화:** 스크린샷, 장르 템플릿, 일괄 편집, 변경 미리보기, 자동 파이프라인.

### 첫 E2E 검증: AI가 제작하는 코인 수집 게임

1. AI가 게임 프로젝트, 바닥, 플레이어, 코인, 장애물, 카메라와 조명을 생성한다.
2. AI가 이동/충돌, 코인 획득, 점수 HUD, 종료 조건을 스크립트로 작성한다.
3. 엔진이 "코인 획득 시 점수 증가", "장애물 충돌", "목표 달성 시 게임 종료"를 검사한다.
4. AI가 실패 로그를 읽고 스스로 수정한 뒤 재검증한다.
5. Futty가 Windows 게임을 빌드하고 실행 파일, 프로젝트, 테스트 결과를 반환한다.

### 성공 지표

- **사람의 필수 GUI 조작 횟수: 0**
- 제작 기능의 MCP/CLI 접근 비율
- 프로젝트 생성부터 테스트·빌드까지의 자동 완주율
- 구조화된 오류의 수정 가능성과 재현성
- 반복 호출 및 대량 편집 시 호출 비용과 안정성

---

이 문서는 **제품 방향과 앞으로 구현할 API의 설계안**이다. 현재 실제 지원 도구는 [futty-mcp 소스](../crates/futty-mcp/src/main.rs)와 [사용 가이드](guide.md)에서 확인한다.
