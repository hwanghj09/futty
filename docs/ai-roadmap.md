# Futty AI 게임 엔진 로드맵

Futty의 목표는 **AI가 씬을 만들고, 다른 AI가 실제 게임 규칙 안에서 플레이하며, 그 결과를 재현할 수 있는 게임 엔진**입니다. 에디터는 사람이 제작 결과를 확인하고, 플레이를 관전하고, 실패 원인을 점검하는 데 사용합니다.

## 현재 기반

Futty MCP는 저장된 씬 생성·조회, 배경 설정, 카메라 추가·선택을 지원합니다. 에디터와 런타임에는 입력 액션, 캐릭터 충돌과 레이캐스트, Rhai 이벤트, 연결형 프리팹, HUD, 프로젝트와 씬 전환, GLB 애니메이션·재가져오기, Windows 내보내기가 있습니다. 아래 기능과 API 이름은 개발 계획입니다. [에디터 사용 가이드](guide.md)

## P0 · AI가 만든 방을 AI가 통과하기

### AI 제작 도구

| 기능 | 구현 범위 |
| --- | --- |
| 씬 구조 조회 | 오브젝트 UUID, 이름, 태그, 부모, 컴포넌트, 에셋 참조를 반환하고 검색·필터를 지원합니다. |
| 오브젝트 편집 | 기본 도형, 카메라, 조명을 생성하고 위치·회전·크기, 이름, 태그, 부모를 수정합니다. |
| 컴포넌트 편집 | 충돌체, 머티리얼, 스크립트, 애니메이션, 오디오의 현재 값을 읽고 수정합니다. |
| 프리팹과 HUD | 스위치나 출구 프리팹을 배치하고 텍스트·버튼·게이지의 레이아웃과 바인딩을 설정합니다. |
| 일괄 변경과 Undo | 한 요청에서 여러 변경을 검사하고 적용합니다. 도중에 실패하면 이전 상태로 복구하고, 성공한 배치는 한 번에 Undo할 수 있게 합니다. |
| 변경 미리보기 | 대상 UUID와 속성의 변경 전후 값을 반환합니다. 열린 씬의 버전이 바뀌었으면 충돌 위치를 알려 줍니다. |
| 씬 검사 | 카메라·시작 씬, 에셋·프리팹·HUD 참조, 씬 전환 대상, 시작 위치와 콜라이더를 검사하고 문제 위치를 반환합니다. |

### AI 플레이 인터페이스

| 기능 | 구현 범위 |
| --- | --- |
| 세션 시작과 초기화 | 씬, 시드, 시작 오브젝트, 최대 틱 수를 지정합니다. 같은 설정으로 세션을 다시 시작할 수 있게 합니다. |
| 플레이어 관찰 | 현재 틱, 시점, 보이는 물체, 목표 진행도, 사용 가능한 상호작용을 반환합니다. 장르에 따라 체력·점수·남은 시간도 제공합니다. |
| 행동 목록 | 이동, 시점 회전, 점프, 상호작용, 대기를 기존 Futty 입력 액션에 매핑합니다. |
| 고정 틱 진행 | 행동을 지정 틱 수 동안 적용하고 다음 관찰과 이벤트를 반환합니다. 잘못된 행동에는 현재 허용되는 행동을 알려 줍니다. |
| 판정 이벤트 | 스위치 작동, 문 열림, 목표 달성, 시간 초과 등 게임 규칙의 결과를 구조화합니다. |
| 헤드리스 실행 | 에디터 창 없이 테스트 세션을 실행하고 성공·실패, 소요 틱, 마지막 상태를 반환합니다. |
| 행동 기록과 재생 | 씬 버전, 엔진 버전, 시드, 틱별 행동을 저장하고 같은 실행 환경에서 결과를 재현합니다. |

**완료 기준**은 제작 AI가 프리팹과 충돌체로 테스트 방을 저장하고, 플레이 AI가 관찰과 입력으로 출구까지 도달하는 것입니다. 같은 씬과 시드에서 같은 행동을 재생하면 같은 판정과 소요 틱이 나와야 합니다.

## P1 · 제작 결과를 보고 고치고 배포하기

### 제작과 에셋

| 기능 | 구현 범위 |
| --- | --- |
| 열린 씬 편집 | MCP 변경을 에디터에 반영하고, 에디터의 저장·Undo 흐름과 연동합니다. |
| 편집 범위 설정 | 제작 AI가 바꿀 수 있는 프로젝트·씬·에셋 범위를 작업마다 지정합니다. |
| 템플릿 프로젝트 | 퍼즐 방, 로비, 연습장, 결과 화면을 시작점으로 제공합니다. |
| 레벨 생성 규칙 | 방 크기, 통로 폭, 시작·종료 위치, 장애물 수를 지정하고 시드로 배치를 재생성합니다. |
| 경로 검사 | 스폰 위치에서 목표와 출구까지 연결된 경로가 있는지 확인하고 막힌 구간을 표시합니다. |
| 에셋 검색과 목록 | 파일, 종류, 크기, GLB 클립, 사용 중인 씬을 조회합니다. |
| 에셋 등록과 교체 | 외부에서 제작한 GLB와 PNG를 등록하고, 기존 UUID를 유지하는 재가져오기와 씬 연결을 자동화합니다. |
| 에셋 생성 연동 | 스프라이트·텍스처·오디오 등 생성 결과를 임포트 후보로 등록하고 규격을 확인합니다. |
| 스크립트 검사 | Rhai 구문과 참조 필드를 검사하고, 오류 위치를 스크립트와 오브젝트 UUID로 연결합니다. |
| 다중 씬 제작 | 시작 씬, 포함할 씬, 전환 조건을 지정하고 로비 → 게임 → 결과 흐름을 검사합니다. |

### 미리보기와 배포

| 기능 | 구현 범위 |
| --- | --- |
| 카메라 캡처 | 지정 카메라의 PNG를 생성하고, 해상도·HUD 포함 여부를 선택합니다. |
| 뷰포트 검사 | 시야 밖의 목표, 겹친 HUD, 화면을 가리는 오브젝트를 스크린샷과 씬 상태로 진단합니다. |
| 테스트 묶음 | 시드별 성공률, 평균 소요 틱, 무효 행동, 막힌 위치를 한 보고서로 집계합니다. |
| 실패 리포트 | 실패한 씬과 시드, 마지막 관찰, 해당 프레임, 반복 재생에 필요한 로그를 묶습니다. |
| 자동 수정 반복 | 실패 기록을 제작 AI에 넘기고, 수정한 씬을 동일한 테스트로 다시 평가해 전후 결과를 비교합니다. |
| 빌드 자동화 | 씬 검사와 플레이 테스트를 실행한 뒤 Windows 빌드의 경로, 포함 씬, 에셋 오류를 반환합니다. |
| 회귀 검사 | 게임의 대표 플레이 기록을 GitHub CI에서 재실행하고 판정·소요 틱의 변화를 기록합니다. |

**완료 기준**은 AI가 변경한 씬을 이미지로 확인하고, 같은 테스트 묶음에서 수정 전후를 비교한 뒤, 통과한 씬을 Windows 게임으로 내보낼 수 있는 것입니다.

## P2 · AI끼리 플레이하고 사람이 관전하기

| 기능 | 구현 범위 |
| --- | --- |
| 에이전트 슬롯과 팀 | AI마다 캐릭터, 팀, 시작 위치, 목표를 배정합니다. |
| 턴제·실시간 진행 | 턴제에서는 모든 AI의 행동을 모아서 처리합니다. 실시간에서는 게임 규칙이 정한 틱 간격으로 입력을 받습니다. |
| 플레이어별 시야 | 각 AI가 자기 시점에서 볼 수 있는 정보만 제공합니다. 관전자 화면에는 전체 진행 상황을 표시할 수 있습니다. |
| 이미지 관찰 | 1인칭 프레임을 관찰 API에 추가하고 상태 기반 관찰과 이미지 기반 관찰을 각각 평가할 수 있게 합니다. |
| 팀 협력 | 같은 팀의 메시지, 핑, 공동 목표, 아이템 전달을 게임 행동으로 지원합니다. |
| AI NPC | Rhai 이벤트와 상태에 따라 경비, 동료, 상인 등을 움직이고 중요한 순간에만 판단을 요청합니다. |
| 웨이포인트와 경로 탐색 | 순찰 지점, 통과 가능한 문, 길찾기 목표를 지정하고 막히면 경로를 다시 계산합니다. |
| 대화와 선택지 | NPC의 대화가 퀘스트 조건, 아이템 지급, 문 개방 같은 게임 규칙과 연결되게 합니다. |
| 난이도 조절 | 플레이 결과에 따라 목표 순서, 시간 제한, 힌트 노출을 조정하고 변경을 기록합니다. |
| 모델 연결 | 외부 AI와 로컬 AI가 같은 관찰·행동 규약을 쓰게 하고, 응답 지연과 재시도는 세션 정책으로 처리합니다. |
| 매치 평가 | 맵·팀 구성·시드를 바꿔 반복 실행하고 완료율, 점수, 시간, 행동 수를 비교합니다. |
| 관전 모드 | 에이전트 시점 전환, 현재 목표, 선택한 행동, 결과를 함께 보여 줍니다. |
| 리플레이 탐색 | 틱 이동, 일시정지, 이벤트 검색, 관전자 카메라 전환을 지원합니다. |
| 장기 진행 저장 | 체크포인트, 방 진행도, 최고 기록과 세션 결과를 저장하고 이어서 실행합니다. |
| 실행 통계 | AI 응답 시간, 시뮬레이션 시간, 관찰 크기, 성공률을 분리해 집계합니다. |

**완료 기준**은 두 AI가 같은 맵에서 각자에게 공개된 정보를 사용해 목표를 수행하고, 사람이 관전 화면과 리플레이에서 승패 원인을 확인하는 것입니다.

## 첫 예제 · Beacon Bot 탈출 테스트

1. **제작 AI**가 Beacon Bot과 벽, 스위치, 출구를 배치합니다. 스위치와 출구는 Rhai 이벤트로 연결합니다.
2. **플레이 AI**가 관찰과 이동·상호작용으로 스위치를 찾고 출구를 엽니다.
3. **검증 모드**가 문이 열리기 전에 통과할 수 없는지, 제한 틱 안에 탈출했는지, 같은 기록을 재생할 수 있는지 검사합니다.
4. **제작 AI**가 실패 로그를 보고 배치를 고칩니다. 같은 테스트로 개선 여부를 확인합니다.

이후 [Pulse Range](../examples/pulse-range/)에서 이동 중 관찰과 조준 입력을, [Prefab Workshop](../examples/prefab-playground/Prefab%20Workshop.futty.scene.ron)에서 원본 편집과 인스턴스 갱신을 검증할 수 있습니다.

## 구현 순서

1. **MCP 씬 편집과 일괄 Undo** — AI가 편집 결과를 안전하게 적용하고 되돌릴 수 있게 합니다.
2. **관찰과 행동 API** — 기존 입력을 통해 AI가 게임 캐릭터를 조작할 수 있게 합니다.
3. **헤드리스 고정 틱 실행과 리플레이** — 제작부터 실패 재현까지 첫 예제를 완성합니다.
4. **이미지 미리보기, 자동 테스트, 빌드** — 결과를 확인하고 수정한 뒤 배포하는 루프를 연결합니다.
5. **여러 AI의 플레이와 관전** — 같은 규칙으로 경기, 협력, 비교 평가를 실행합니다.
