# Futty Idea Interview — 게임 아이디어 인터뷰

## 목적

Futty는 AI가 게임을 쉽게 만들도록 하는 도구이지만 **어떤 게임을 만들고 싶은지 결정하는 주체는 사용자**다. “FPS 게임 만들어”처럼 짧은 요청만으로 오버워치형 영웅 슈터, 발로란트형 전술 슈터, 둠형 고속 PvE 중 하나를 AI가 마음대로 선택해서는 안 된다.

사용자의 머릿속에 있는 **장면, 감정, 핵심 재미, 플레이 방식, 분위기, 금기사항**을 질문을 통해 발견한다. 질문을 많이 하더라도 사용자가 실제로 선택·상상할 수 있는 질문이어야 한다.

## 적용 조건

**이 스킬을 먼저 적용한다:**
- 게임 아이디어 구상, 컨셉, 기획안, 장르 탐색 요청
- “FPS 만들어”, “공포게임 만들어줘”, “2D RPG 만들자” 등 해석의 여지가 큰 제작 요청
- “내 생각을 잘 이해해 줘”, “나한테 많이 물어봐”, “기획 질문해줘” 등 대화식 설계 요청
- 게임 참조작만 언급하고 해당 작품의 어떤 경험을 원하는지 불분명한 경우

**인터뷰를 강요하지 않는다:**
- 사용자 요구가 플레이 루프, 모드, 규칙, 범위까지 이미 구체적이고 바로 구현/수정하라고 한 경우
- 버그 수정, MCP 연결, 엔진 설정 등 새 게임 아이디어 탐색과 무관한 작업
- 사용자가 “질문하지 말고 알아서 만들어” 또는 도중에 “이제 진행해”라고 한 경우. 이때는 미정 사항을 AI의 임시 가정으로 표시하고 실행한다.

이미 이전 메시지에서 답한 내용은 다시 묻지 않는다. 사용자가 도중에 마음을 바꾸면 최신 선택을 우선한다.

## 단계별 대화 절차

### 1단계 — 머릿속 게임 이미지 찾아내기

1. 사용자의 표현을 한 문장으로 되짚되 미정 사항은 확정하지 않는다.
2. 가장 큰 방향을 결정하는 **선택형 질문 2~3개 + 상상력을 묻는 열린 질문 1개**로 시작한다.
3. 각 선택형 질문은 **A/B/C/D** 등 서로 다른 2~4개 옵션과 1줄의 플레이 느낌을 제시한다.
4. “직접 설명 / 두 가지 혼합 / 아직 모르겠음”을 허용한다.
5. 참고 게임 이름을 쓴다면 **무엇을 참고하는지** 물어본다. 캐릭터·맵·아트의 원작 복제를 전제로 하지 않는다.
6. “1-A, 2-C처럼 짧게 답해도 되고 자유롭게 설명해도 된다”고 안내한다.

중요한 첫 열린 질문:
**“머릿속에서 게임이 시작되는 첫 30초의 장면은 어떤 모습인가요?”**

### 2단계 — 답변에 따라 깊이 있는 질문 진행

- 한 차례 답변을 받으면 **확정된 내용 1~2줄**을 짚고, 해당 선택에서 파생되는 질문 2~4개를 새로 한다.
- 질문은 상황에 따라 **3~6개 라운드, 총 10~25개 수준의 의미 있는 결정**을 탐색할 수 있다. 사용자가 특히 많이 묻기를 원하면 더 깊게 파고든다. 개수를 채우려고 반복하지 않는다.
- 질문 순서는 **상상한 감정/판타지 → 실제 조작과 핵심 루프 → 승리/실패/게임 모드 → 월드·스토리·아트·사운드 → 차별화·MVP**를 기본으로 한다.
- 질문은 항상 사용자의 답에 따라 분기한다. “빠른 게임”은 이동 속도인지, 한 판 길이인지, 적이 죽는 속도인지 구분해서 묻는다.
- “잘 모르겠음”이면 서로 다른 구체적 플레이 장면 2~3개를 짧게 제안하고 선택하도록 돕는다.
- 답이 충돌하면 둘의 우선순위나 결합 방식을 물어본다. 임의로 하나를 지우지 않는다.
- 사용자가 “질문 너무 많아”라고 하면 우선순위가 높은 남은 질문 하나만 묻거나 바로 브리프를 작성한다.
- 사용자가 “계속 물어봐”라고 하면 확정되지 않은 새로운 차원을 탐색한다.
- 불필요하게 장문으로 답을 매번 다시 쓰지 않는다.

### 3단계 — 사용자의 상상과 실제 플레이 연결

기획을 끝내기 전에 가능한 한 아래 항목을 이해한다.

| 축 | 확인하려는 내용 |
| --- | --- |
| 플레이어 판타지 | 누구로서 어디서 무엇을 하며 어떤 감정을 느끼는가? |
| 첫 경험 | 게임 첫 30~60초 화면과 조작 |
| 핵심 재미 | 가장 중요한 2~3개 재미 / 사람들이 다시 하고 싶은 이유 |
| 루프 | 행동 → 피드백/보상 → 세계의 변화 → 다음 행동 |
| 목표 | 승리/패배, 스테이지와 라운드 길이 |
| 조작 | 2D/3D, 카메라, 난도, 이동/전투/상호작용 |
| 게임 모드 | 싱글, 협동, PvP, 플레이 인원 |
| 표현 | 세계관·비주얼·캐릭터·애니메이션·소리 |
| 차별화 | 비슷한 게임과 반드시 다른 요소 |
| MVP | 첫 번째 플레이 가능 버전의 필수 3개, 제외할 요소 |

모든 항목을 필수 설문처럼 물어보지 않는다. 이미 충분히 특정되고 중요하지 않은 선택은 가정으로 남겨도 된다.

### 4단계 — 게임 브리프로 인수인계

인터뷰가 충분하거나 사용자가 다음 단계로 가길 원하면 다음 형식으로 정리한다.

1. **한 문장 피치** — 사용자가 상상한 게임을 사용자의 어휘로 표현
2. **확정된 비전** — 사용자가 직접 택한 것만 기재
3. **핵심 재미 3가지 / 차별화 포인트**
4. **게임플레이 핵심 루프**와 승리·실패 판정
5. **첫 5~15분 플레이** — 장면 → 행동 → 결과 → 다음 목표
6. **아트·애니메이션·사운드 방향**
7. **MVP 필수 / 추후 확장 / 싫거나 금지한 요소**
8. **남은 질문과 AI 임시 가정** — 확정된 사항과 구분
9. **테스트 가능한 수락 기준**

사용자가 확신이 없으면 브리프를 임시 상태로 두고 추가 질문한다. 충분하면 기획으로 전환할지 한 번 제안하되, 사용자가 이미 진행을 지시했다면 다시 승인받지 않는다.

### 5단계 — 다른 Futty 스킬로 전달

- 아이디어 탐색 완료 → [futty-game-design](../futty-game-design/SKILL.md): 장면, 규칙, 기획 구조 작성
- 원스톱 제작 요청 → [futty-one-shot-game](../futty-one-shot-game/SKILL.md): 자산·모델·애니메이션·오디오·게임 구현
- 엔진 구현 가능 범위는 [최종 목표](../../../docs/FUTTY_FINAL_GOAL.md) 및 실제 Rust/MCP 코드를 검토한다. 목표에만 있는 2D·멀티·생성 모델을 이미 완성한 것처럼 말하지 않는다.

## 질문의 품질 원칙

- 짧고 구체적인 질문을 많이 한다. **20개를 한 메시지에 몰아 넣지 않는다.**
- 선택지는 **정답이 아닌 상상을 시작할 발판**이다. 직접 설명이나 혼합을 항상 환영한다.
- “재밌는가?”보다 “무엇을 할 때 가장 재미를 느꼈으면 하는가?”가 낫다.
- 참고 게임의 어떤 면을 좋아하는지 물어야 한다. 이름 하나로 게임 전체를 추측하지 않는다.
- 질문 수보다 **사용자의 생각을 정확히 이해하는 것**이 중요하다.
- 과거 답을 기억하고 사용자 선택과 AI의 제안을 명확히 구분한다.
- 기획 단계에서 충분히 합의되지 않은 요소를 곧바로 게임 코드나 확정 사양으로 만들지 않는다.
- 인터뷰 자체가 목표가 아니며, 언제든 기획/제작으로 진행할 수 있어야 한다.

상황별 질문 목록은 [질문 분기표](references/question-bank.md), 예시는 [대화 예시](references/examples.md)를 참고한다.

## 대표 첫 응답 — “FPS 게임 만들어줘”

좋아요. FPS도 원하는 플레이 경험에 따라 아주 다른 게임이 될 수 있어요. 어떤 FPS를 상상하나요?

**1. 전투 느낌은 어떤 쪽인가요?**
A. 오버워치처럼 서로 다른 영웅 능력과 팀 조합이 중요한 게임
B. 발로란트처럼 정밀 사격, 전술과 라운드 승부가 중요한 게임
C. 둠처럼 빠르게 움직이며 적을 연속으로 쓰러뜨리는 게임
D. 위 특징을 섞거나 완전히 새로운 방식

**2. 가장 기대되는 재미는?**
A. 팀워크와 역전 / B. 조준 실력과 긴장감 / C. 성장·아이템 수집 / D. 다른 재미

**3. 게임이 시작되는 첫 장면은 어떻게 상상하나요?**
예: 네온사인 도시에서 팀이 출동, 폐공장에 숨어 접근, 괴물들로 가득 찬 기지에서 탈출.

숫자와 알파벳으로 짧게 답하거나 자유롭게 이야기해도 됩니다. 참고 게임들은 **플레이 느낌을 비교하기 위한 예시**일 뿐 원작 복제를 뜻하지 않습니다.
